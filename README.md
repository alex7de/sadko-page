# sadko-page

Одностраничная инструкция по подключению к VPN через клиент **Happ**.

Два входа:

- **персональная ссылка** `/u/<token>` — основной способ раздачи. Открывший
  видит **ровно свой** профиль: своё имя, свой QR, свою ссылку. Ни соседа по
  группе, ни тем более чужой группы в ответе нет — это не скрытие стилями,
  чужих данных физически нет в HTML. Пароль не спрашивается, cookie не ставится;
- **пароль роли** — обзорный доступ владельца: весь список профилей своей
  группы на одной странице. Пользователям пароль раздавать не нужно: общий
  пароль в чате на два десятка человек утекает наружу за считанные дни.

Обслуживаются две независимые группы пользователей (роли). **Каждая роль
видит только свои конфиги** — данные чужой роли физически не попадают в
HTML-ответ.

Никаких конфигов, адресов, ключей и паролей в этом репозитории нет и быть не
должно. Всё приходит **только через переменные окружения**.

## Стек

Node 20+, Express, qrcode, cookie-parser. Без БД, без фронтенд-фреймворков,
без сборщика, без внешних CDN — все ресурсы (в том числе QR-коды) инлайнятся
в HTML.

## Переменные окружения

Обязательные (без них процесс не стартует и пишет в stderr, чего не хватает):

| Переменная | Назначение |
| --- | --- |
| `PAGE_PASSWORD_SADKO` | Пароль первой роли (`sadko`) |
| `PAGE_PASSWORD_ALEXDE` | Пароль второй роли (`alexde`) |
| `SESSION_SECRET` | Секрет для HMAC-подписи сессионной cookie. Длинная случайная строка |
| `PROFILES_SADKO_JSON` | Профили первой роли, JSON-массив (см. формат ниже) |
| `PROFILES_ALEXDE_JSON` | Профили второй роли, JSON-массив |
| `ROUTING_LINK` | Ссылка `happ://routing/onadd/...` с routing-профилем «РФ мимо VPN». Общая для обеих ролей, секретом не является |

Необязательные:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Порт HTTP-сервера |
| `COOKIE_INSECURE` | не задана | `1` — снять флаг `Secure` с cookie. Нужно **только** для локального запуска по `http://localhost`. В проде не задавать |
| `MANUAL_SADKO_JSON` | — | Параметры для ручного ввода (роль `sadko`) |
| `MANUAL_ALEXDE_JSON` | — | Параметры для ручного ввода (роль `alexde`) |
| `BRAND_SADKO` | `Садко-VPN` | Заголовок раздела подписок для роли `sadko` |
| `BRAND_ALEXDE` | `ALEXDE VPN` | Заголовок раздела подписок для роли `alexde` |
| `TRUST_PROXY` | не задана | `1` — доверять `X-Forwarded-For` (нужно, если перед контейнером стоит reverse proxy; влияет на лимит попыток входа по IP) |

### Формат `PROFILES_*_JSON`

JSON-массив объектов. Каждый объект — один человек, его ссылка на подписку и
токен его персональной страницы:

```json
[
  {"name": "Имя", "sub": "https://<хост-подписки>/<uuid>", "token": "<32 hex>"},
  {"name": "Другое имя", "sub": "https://<хост-подписки>/<uuid>", "token": "<32 hex>"}
]
```

Поля:

- `name` — как подписать карточку (обязательно);
- `sub` — ссылка на подписку, из неё делается QR и deeplink (обязательно);
- `token` — адрес персональной страницы: `/u/<token>` (обязательно). Ровно 32
  символа `[0-9a-f]`, генерируется `openssl rand -hex 16`. Токены **уникальны
  глобально**, между всеми ролями: совпадение означало бы, что по одной ссылке
  открывается чужой конфиг, поэтому процесс на старте падает;
- `note` — необязательная строка-пояснение под именем.

Токен — это и есть ключ доступа к чужой персональной странице, поэтому берите
его из `openssl rand -hex 16`, а не придумывайте. Заменить человеку ссылку
(например, если он переслал её в общий чат) = поставить новый `token` и
перезапустить контейнер; старая ссылка сразу отдаёт 404.

### Формат `MANUAL_*_JSON`

Параметры для ручного ввода в клиентах без сканера QR. Либо один объект, либо
массив объектов (например, «дом» и «улица»):

```json
[
  {
    "label": "Название профиля",
    "address": "<адрес сервера>",
    "port": "<порт>",
    "pbk": "<public key Reality>",
    "sid": "<short id>",
    "sni": "<sni>",
    "fp": "<fingerprint>",
    "flow": "<flow>"
  }
]
```

Ключи произвольные — что передадите, то и покажется в таблице. `label`
используется как заголовок блока и в таблицу не попадает.

## Локальный запуск

```bash
npm install
PAGE_PASSWORD_SADKO='пароль-1' \
PAGE_PASSWORD_ALEXDE='пароль-2' \
SESSION_SECRET="$(openssl rand -hex 32)" \
COOKIE_INSECURE=1 \
PROFILES_SADKO_JSON='[{"name":"Тест","sub":"https://EXAMPLE-MARKER/1","token":"'"$(openssl rand -hex 16)"'"}]' \
PROFILES_ALEXDE_JSON='[{"name":"Я","sub":"https://EXAMPLE-MARKER/2","token":"'"$(openssl rand -hex 16)"'"}]' \
ROUTING_LINK='happ://routing/onadd/<base64>' \
npm start
```

Открыть `http://localhost:3000`, ввести один из паролей — роль определяется
тем, какой пароль подошёл, выбора роли в форме нет. Персональная страница —
`http://localhost:3000/u/<token>`, пароль там не нужен.

Удобнее держать переменные в `.env` (файл в `.gitignore`) и запускать через
`env $(grep -v '^#' .env | xargs) npm start` или через `--env-file=.env`
(Node 20+).

## Запуск в Docker

```bash
docker build -t sadko-page .
docker run -d -p 3000:3000 \
  -e PAGE_PASSWORD_SADKO=... \
  -e PAGE_PASSWORD_ALEXDE=... \
  -e SESSION_SECRET=... \
  -e PROFILES_SADKO_JSON='[...]' \
  -e PROFILES_ALEXDE_JSON='[...]' \
  -e ROUTING_LINK='happ://routing/onadd/...' \
  sadko-page
```

На Dockhost все перечисленные переменные задаются в настройках контейнера как
секреты. Контейнер слушает `3000`, HTTPS терминируется платформой, поэтому
`COOKIE_INSECURE` там задавать **не нужно**.

## Безопасность

- Сессия — подписанная HMAC-SHA256 cookie `sess` вида
  `<role>.<expiry>.<signature>`, флаги `httpOnly`, `SameSite=Strict`,
  `Secure` (снимается только через `COOKIE_INSECURE=1`), срок 30 дней.
  Своей БД и библиотеки аутентификации нет — паролей всего два, общих.
- Пароли сравниваются через `crypto.timingSafeEqual` по SHA-256-дайджестам
  фиксированной длины, поэтому длина введённого пароля не утекает.
- Персональная ссылка `/u/<token>`: 32 hex-символа — 128 бит, перебор
  бессмысленен. Профиль ищется одним `Map.get` по индексу, построенному на
  старте. Неизвестный токен → 404 с одной фразой «Ссылка недействительна»: ни
  формы входа, ни названий групп, ни намёка на то, сколько профилей заведено.
- Лимит попыток входа: 10 неудач с одного IP за 15 минут. Тот же счётчик
  считает промахи по `/u/<token>`, поэтому перебор токенов упирается в него
  же; удачное попадание счётчик не сбрасывает.
- `Referrer-Policy: no-referrer` на всех ответах (и `<meta name="referrer">` в
  разметке): токен стоит в URL и иначе утёк бы в реферере при переходе со
  страницы в App Store, Google Play или на GitHub.
- На всех ответах `X-Robots-Tag: noindex, nofollow`, в `/robots.txt` —
  `Disallow: /`.
- Роль читается из подписи cookie, и в HTML рендерится **только её** блок.
  На персональной странице в разметку попадает **один** профиль — тот, чей
  токен в URL. Скрытия через CSS нигде нет.
